Step 1, One-time vault setup

Create the free canonical vault (about 3 minutes)
  1. Make a free account at github.com (any anonymous-enough username).
  2. Create a private gist: gist.github.com, new gist. Name the file exactly avalanche-content.json, put {} as contents, create.
  3. Copy the gist ID from the URL: gist.github.com/you/THIS_PART
  4. Settings, Developer settings, Personal access tokens, Generate (classic), tick gist only, copy token.
  5. Paste both below. That token is your publishing power, never share it.

Step 2, Publish

Pushing writes your content to the vault. Every mirror loads the newest version on visit. Inbox replies marked Publish will appear on the answers board. Or use local file export if you host directly.

Copy content.js pastes into js/content.js for direct file hosts. Backup doubles as content.remote.json for mirrors.

Local file mode (no gist)

If you host from the file directory, just export and drop the files: js/content.js + data/tips.json handling is local. Inbox here reads from data/tips.json when served via the local panel or PHP host.

Publish to live site (GitHub repo)

This is the button that actually makes stories live. It writes js/content.js and data/site.json straight to your GitHub repo, and Cloudflare redeploys seattleavalanche.online in about a minute.

Token needs the classic repo scope: GitHub > Settings > Developer settings > Personal access tokens > Generate (classic). The gist vault above is optional; this repo push is what publishes.
